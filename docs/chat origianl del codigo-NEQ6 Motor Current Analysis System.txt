# 3. Current Measurement Hardware Specification

## 3.1 Measurement Requirements

The current measurement channel shall support:

```text
Measurement range:     0 A to 2 A continuous
Maximum allowed input: 2 A for normal operation
Measurement point:     Motor supply return path of selected axis
Output to Flipper:     0 V to approximately 2 V at 2 A
```

A low-side shunt topology is recommended because it keeps the sensed voltage close to ground and simplifies protection of the Flipper Zero ADC.

---

## 3.2 Recommended Shunt and Gain Configuration

The recommended design uses a low-value shunt and a precision current-sense amplifier. This reduces power dissipation and improves ADC resolution.

### Recommended values

| Parameter | Value | Notes |
|---|---:|---|
| Shunt resistance | 0.050 Ω | 1% tolerance, low temperature coefficient |
| Maximum continuous current | 2.0 A | Software measurement range |
| Shunt voltage drop at 2 A | 0.100 V | `V = I × R = 2 A × 0.050 Ω` |
| Power dissipation at 2 A | 0.200 W | `P = I² × R = 4 × 0.050` |
| Recommended resistor power rating | 1 W minimum, 2 W preferred | Gives thermal margin |
| Resistor tolerance | 1% or better | Required for calibration accuracy |
| Temperature coefficient | ≤ 50 ppm/°C recommended | Reduces drift during heating |
| Current-sense amplifier gain | 20 V/V | Example: INA180A1 or equivalent |
| Amplifier output at 2 A | 2.0 V | `0.100 V × 20` |
| System sensitivity | 1.0 V/A | Convenient calibration factor |
| Flipper ADC full-scale reference | 3.3 V nominal | STM32WB ADC range |
| Ideal 12-bit LSB | 3.3 V / 4096 = 0.806 mV | Before amplification |
| Ideal current resolution | 0.806 mA/LSB | `0.806 mV / 20 / 0.050 Ω` |

This configuration provides a good compromise between:

- Low voltage drop,
- Low power dissipation,
- Good ADC resolution,
- Simple 3.3 V-compatible signal conditioning.

---

## 3.3 Simpler Direct-Connection Alternative

A simpler direct shunt connection is possible if the amplifier is omitted.

| Parameter | Value |
|---|---:|
| Shunt resistance | 0.100 Ω |
| Voltage drop at 2 A | 0.200 V |
| Power dissipation at 2 A | 0.400 W |
| Recommended resistor rating | 1 W minimum, 2 W preferred |
| Ideal current resolution | approximately 8 mA/LSB |

This direct configuration is simpler but has lower resolution. The amplified 0.050 Ω design is preferred for the final system.

## 3.5 Protection Circuit

The Flipper Zero ADC input shall be protected against:

- Overvoltage,
- ESD,
- Transients,
- Amplifier output faults,
- Accidental connection errors.

Recommended protection network:

```text
Amplifier output
     |
   1 kΩ series resistor
     |
     +---- 100 nF ---- GND
     |
     +---- Schottky diode to 3V3
     |
     +---- Schottky diode to GND
     |
   Flipper ADC GPIO
```

Recommended component behavior:

| Item | Purpose |
|---|---|
| 1 kΩ series resistor | Limits current into ADC pin and clamp diodes |
| 100 nF capacitor | Filters high-frequency noise |
| Schottky clamp to 3V3 | Prevents ADC pin from rising significantly above 3.3 V |
| Schottky clamp to GND | Prevents ADC pin from going significantly below ground |
| Optional TVS diode | Additional protection for long cables or noisy environments |

The amplifier output at 2 A is 2.0 V, well below the 3.3 V ADC limit. The protection components are primarily for transient and fault protection.

The NEQ6 has two axes:

```text
Axis 1: RA

```

The current shunt shall be installed in the return path of the axis being measured.

Two practical implementation options are allowed:

### Option A: Manual shunt connection

# 5. Communication Protocol

A compact binary protocol is recommended. All multibyte values shall be little-endian unless otherwise stated.

## 5.1 Packet Framing

Each packet shall be framed as:

```text
+-------+-------+------+----------------+-------+
| MAGIC | LEN   | TYPE | PAYLOAD        | CRC8  |
+-------+-------+------+----------------+-------+
```

Definitions:

| Field | Size | Description |
|---|---:|---|
| MAGIC | 1 byte | Constant `0xA5` |
| LEN | 1 byte | Payload length |
| TYPE | 1 byte | Packet type |
| PAYLOAD | 0 to 250 bytes | Type-specific data |
| CRC8 | 1 byte | CRC over TYPE and PAYLOAD |

Maximum recommended BLE notification payload should remain below the negotiated MTU.

# 6. Clock Synchronization

Clock synchronization is critical because the current sample is physically acquired on the Flipper Zero, while the angular position is obtained by the PC from the NEQ6 using the PC timeline.

The system shall estimate the relationship:

```text
PC_time = Flipper_time + offset
```

where `offset` is the estimated time offset between the Flipper time base and the PC monotonic time base.

---

## 6.1 Synchronization Procedure

The synchronization procedure shall be performed:

1. Manually when the user presses the synchronization button.
2. Automatically at the beginning of every measurement.
3. Optionally immediately after a measurement completes, to estimate drift.

The procedure shall consist of multiple synchronization exchanges.

Recommended number of exchanges:

```text
Manual sync:     20 to 100 exchanges
Automatic sync:  30 to 100 exchanges
```

The exact number may be configurable.

---

## 6.2 Offset Estimation

For each synchronization exchange `i`:

```text
t1_i = PC monotonic time just before sending CMD_SYNC_REQ
tf_i = Flipper timestamp included in RESP_SYNC
t2_i = PC monotonic time just after receiving RESP_SYNC
```

Compute:

```text
rtt_i = t2_i - t1_i
mid_i = (t1_i + t2_i) / 2
offset_i = tf_i * 1000 - mid_i
```

All values should be handled in nanoseconds internally.

The final offset shall be a robust estimate, for example:

```text
offset = median(offset_i for low-RTT samples)
```

The synchronization algorithm should discard or down-weight samples with unusually high RTT.

Recommended selection:

```text
Use the 25% to 50% lowest RTT samples.
Compute median offset.
Compute robust standard deviation or MAD-based uncertainty.
```

---

## 6.3 Synchronization Quality Metrics

The GUI shall display:

```text
Last synchronization time
Number of synchronization samples
Estimated offset
Offset uncertainty
Minimum RTT
Median RTT
Maximum RTT
Drift estimate, if available
Synchronization status
```

Example display:

```text

Offset: +12.43 ms
Offset uncertainty: ±1.8 ms
RTT min/median/max: 18.2 / 24.5 / 61.3 ms
Drift: +0.8 ppm

```

Synchronization quality classification may be:

| Status | Meaning |
|---|---|
| Good | Low RTT, low offset dispersion |
| Fair | Acceptable but variable latency |
| Poor | High RTT or unstable offset |
| Failed | Synchronization could not be completed |

The Start Measurement function shall require at least a Fair synchronization result. If synchronization is Poor, the application shall warn the user and optionally allow an override if the user accepts reduced timing confidence.

---

## 6.4 Drift Compensation

For long measurements, the Flipper time base may drift relative to the PC clock.

The application shall support optional pre- and post-measurement synchronization.

If both pre- and post-sync are available:

```text
offset_pre  at time t_pre
offset_post at time t_post

drift_rate = (offset_post - offset_pre) / (t_post - t_pre)
```

For a sample at Flipper time `t_f`:

```text
offset(t_f) = offset_pre + drift_rate * (t_f - t_pre)
```

If post-sync is unavailable, the system shall assume zero drift but increase timestamp uncertainty according to the expected oscillator stability.

---

## 6.5 Timestamp Conversion

For every current sample:

```text
flipper_time_ns = flipper_time_us * 1000
pc_monotonic_ns = flipper_time_ns + offset(flipper_time_ns)
```

The application shall maintain a wall-clock anchor:

```text
wall_anchor_ns = time.time_ns()
mono_anchor_ns = time.monotonic_ns()
```

Then the CSV wall-clock timestamp is:

```text
pc_timestamp_ns = wall_anchor_ns + (pc_monotonic_ns - mono_anchor_ns)
```

This gives sub-second precision in the CSV while preserving accurate relative timing from the monotonic clock.

The PC application shall communicate with the NEQ6 through the already installed UART-to-serial converter.

The exact low-level command set may be based on:

- Sky-Watcher / EQ6 direct serial protocol,
- EQMOD-compatible command handling,
- or an ASCOM/serial bridge if required by the environment.

The software architecture shall isolate the mount protocol inside a dedicated driver module so that the protocol implementation can be changed without affecting the rest of the application.

Where:

```python

```

---

## 7.3 Angular Position Acquisition

The Python application shall continuously poll the selected axis position during measurement.

Recommended polling rate:

```text
10 Hz to 50 Hz, depending on serial protocol responsiveness
```

Each position sample shall be timestamped on the PC.

The recommended timestamp for a position query is:

```text
t_position = (t_request_sent + t_response_received) / 2
```

This reduces serial latency bias.

The application shall store:

```text
pc_monotonic_ns
pc_timestamp_ns
axis
raw_reported_angle_deg
unwrapped_angle_deg
```

---

## 7.4 Angle Unwrapping

The mount may report angle modulo 360 degrees. The application shall maintain an unwrapped angle.

Algorithm:

```text
delta = current_raw_angle - previous_raw_angle

if delta > +180:
    delta -= 360
elif delta < -180:
    delta += 360

unwrapped_angle += delta
```

This produces a continuous angle suitable for detecting complete revolutions.

---

## 7.5 Revolution Detection

A complete revolution shall be defined as 360 degrees of unwrapped axis motion in the selected direction.

For `N` requested revolutions:

```text
target_motion_deg = 360 * N
```

A revolution boundary shall be registered when the unwrapped angle crosses:

```text
start_angle + 360 * k
```

for integer `k = 1, 2, ..., N`.

Each sample shall be assigned:

```text
revolution_index
relative_angle_deg
```

where:

```text
relative_angle_deg = unwrapped_angle_deg - revolution_start_angle_deg
```

and is usually normalized to the range:

```text
0 <= relative_angle_deg < 360
```

3. Application creates a unique session start timestamp.
4. Application generates the raw CSV filename.

2. Stop Flipper sampling.

5. Interpolate angular position for each current sample.
6. Assign revolution indices and relative angles.
7. Save raw CSV.
8. Save metadata JSON.
9. Generate default processed view if required.
10. Display graphs and statistics.

# 12. Angular Statistics and Circular Quantities

Angle is circular. A naive arithmetic mean is invalid near the 0/360 boundary.

The application shall use circular statistics for angular averaging.

For angles `theta_i` in radians:

```text
C = sum(cos(theta_i))
S = sum(sin(theta_i))
R = sqrt(C^2 + S^2) / n
mean_angle = atan2(S, C)
```

Circular variance:

```text
circular_variance = 1 - R
```

Circular standard deviation:

```text
circular_std = sqrt(-2 * ln(R))
```

for `R > 0`.

For small angular dispersion, an approximate circular standard error may be:

```text
circular_se = sqrt((1 - R) / (n * R))
```

The application shall convert circular standard deviation from radians to degrees when storing CSV values.

---

# 13. Averaging and Uncertainty Propagation

## 13.1 Averaging Model

For averaging factor `M`, the application shall group raw samples within each revolution into non-overlapping blocks of `M` samples.

For each block:

```text
n = number of samples in block, normally M
```

The block shall produce one processed sample.

If the final block contains fewer than `M` samples, it may be discarded or stored with `sample_count < M`, depending on configuration. The recommended default is to store it but flag it as partial.

---

## 13.2 Time Averaging

For a block with timestamps `t_i`:

```text
mean_timestamp = mean(t_i)
```

Timestamp uncertainty shall combine several contributions:

```text
u_time_block = block_duration / sqrt(12)
u_sync       = synchronization offset uncertainty
u_mount      = mount position timestamp uncertainty
u_jitter     = sampling jitter estimate, if available
```

Combined timestamp uncertainty:

```text
u_timestamp = sqrt(u_sync^2 + u_mount^2 + u_time_block^2 + u_jitter^2)
```

The term `block_duration / sqrt(12)` represents the uncertainty due to representing a finite time interval by a single representative time.

---

## 13.3 Current Averaging

For current samples `I_i`:

```text
current_mean = mean(I_i)
current_std  = std(I_i, ddof=1)
```

Random current uncertainty:

```text
u_current_random = current_std / sqrt(n)
```

Additional uncertainty contributions:

```text
u_adc_quantization = current_lsb / sqrt(12)
u_calibration      = calibration uncertainty
u_noise            = estimated noise floor if n = 1
```

Combined current uncertainty:

```text
u_current = sqrt(u_current_random^2 + u_adc_quantization^2 + u_calibration^2)
```

---

## 13.4 Angle Averaging

For angle samples inside a block, the application shall compute the circular mean and circular standard deviation.

Angle uncertainty shall include:

1. Angular dispersion inside the block.
2. Angular motion caused by timestamp uncertainty.
3. Interpolation uncertainty from NEQ6 position sampling.

Let:

```text
omega = local angular speed in deg/s
u_time = timestamp uncertainty in seconds
```

Then:

```text
u_angle_time = abs(omega) * u_time
```

Combined angular uncertainty:

```text
u_angle = sqrt(u_angle_circular^2 + u_angle_time^2 + u_angle_interp^2)
```

where `u_angle_circular` is derived from the circular standard error.

---

## 13.5 Cross-Revolution Averaging

For multiple revolutions, the application shall compute an average curve.

Recommended method:

1. For each revolution, produce temporally averaged blocks.
2. Interpolate each revolution onto a common phase grid.
3. Average current values at each phase grid point.
4. Propagate uncertainties.

Example phase grid:

```text
0.0, 0.5, 1.0, ..., 359.5 degrees
```

or a grid based on the number of averaged blocks.

For `k` revolutions at a given phase point:

```text
current_mean_average = mean(current_i)
```

Uncertainty of the mean:

```text
u_current_average = sqrt(sum(u_current_i^2)) / k
```

For angular average at a fixed phase grid point, the angle is usually the grid angle, but the application may still store the circular mean and dispersion of the interpolated angle values.

---

## 13.6 Propagation When Averaging Already Processed Data

If the application later averages already processed samples, uncertainties shall propagate as independent uncertainties unless correlation is explicitly known.

For `k` processed values with uncertainties `u_i`:

```text
mean_value = sum(value_i) / k
u_mean = sqrt(sum(u_i^2)) / k
```

This applies to:

- Current,
- timestamp,
- angle uncertainty when linear approximation is valid.

For angle, circular statistics shall still be used for the mean direction.

# 18. Timing Accuracy and Association of Current with Angle

The physical measurement chain is:

```text
Motor current -> shunt -> amplifier -> Flipper ADC -> Flipper timestamp -> BLE -> PC
Mount angle   -> NEQ6 electronics -> serial response -> PC timestamp -> interpolation
```

The application shall associate each current sample with an angular position by interpolating the NEQ6 position timeline at the synchronized current-sample time.

For each current sample:

```text
t_current_pc = synchronized PC time of current sample
theta_current = interpolate(NEQ6_position_timeline, t_current_pc)
```

The interpolation shall use unwrapped angle values.

For plotting, the angle may be reduced modulo 360 or relative to revolution start.

---

## 18.1 Position Interpolation

The position timeline consists of samples:

```text
(t_j, theta_unwrapped_j)
```

For a current sample time `t`, use linear interpolation:

```text
theta(t) = theta_j + (theta_{j+1} - theta_j) * (t - t_j) / (t_{j+1} - t_j)
```

If `t` lies outside the measured position range by more than a configurable tolerance, the sample shall be flagged or discarded.

Recommended tolerance:

```text
50 ms to 200 ms, depending on mount polling rate
```

---

## 18.2 Timing Uncertainty Budget

The final timing uncertainty may include:

```text
u_flipper_timestamp     Quantization and ISR delay
u_ble_sync              Clock synchronization uncertainty
u_drift                 Clock drift during measurement
u_mount_polling         NEQ6 position polling interval
u_mount_serial_latency  Serial request/response latency
u_interpolation         Linear interpolation approximation
```

The application shall store a practical combined timestamp uncertainty in processed files.

For raw files, the application may store the raw timestamps and synchronization metadata instead of a full per-sample uncertainty estimate.

# 19. Error Handling

The application shall handle errors gracefully.

## 19.1 NEQ6 Errors

The application shall detect:

- Serial port not found.
- Serial timeout.
- Mount not responding.
- Invalid axis.
- Invalid speed.
- Motion not progressing.
- Limit switch or mount fault, if reported.

On critical mount errors:

```text
Stop motion.
Stop recording.
Preserve acquired data.
Display error message.
```

---

## 19.2 Flipper Errors

The application shall detect:

- BLE connection failure.
- BLE disconnection.
- Unsupported sampling rate.
- Buffer overrun.
- Sample sequence gaps.
- Invalid calibration.
- ADC saturation.

On buffer overrun or sample gaps:

```text
Mark affected regions in flags.
Do not fabricate raw samples.
Warn the user.
```

---

## 19.3 Synchronization Errors

If automatic synchronization fails before measurement:

```text
Do not start measurement by default.
Display synchronization diagnostics.
Allow user retry.
Optionally allow override with warning.
```

If synchronization fails during measurement, the application shall continue recording if possible but flag the dataset with degraded synchronization quality.

## 1. ¿Por qué se propuso un amplificador?

Un amplificador de corriente cumple varias funciones:

1. **Aumentar la señal medida**  
   Si el shunt es muy pequeño, la tensión es pequeña. Por ejemplo:

   ```text
   Rshunt = 0.05 Ω
   I = 2 A
   Vshunt = 0.1 V
   ```

   0.1 V es una señal válida, pero ocupa poca parte del rango del ADC de 3.3 V.

2. **Mejorar la resolución efectiva**  
   El ADC del Flipper Zero es de 12 bits. Con una señal pequeña, solo se usa una parte de los 4096 niveles.

3. **Permitir un shunt más pequeño**  
   Un shunt más pequeño genera menos caída de tensión y menos disipación, pero produce una señal más débil. El amplificador compensa esa señal débil.

4. **Agregar filtrado y acondicionamiento**  
   Un amplificador puede servir como buffer y permitir un filtro RC más controlado antes del ADC.

5. **Reducir el efecto del ruido**  
   Una señal más grande suele mejorar la relación señal/ruido frente a ruido eléctrico del entorno.

Pero si la resolución directa es suficiente, **se puede eliminar el amplificador**.

---

## 2. Conexión directa del shunt al ADC

Si la fuente está limitada a 2 A y el shunt se elige correctamente, la conexión directa es viable.

Una opción simple y razonable es:

```text

```

### Cálculos con 0.100 Ω

| Parámetro | Valor |
|---|---:|
| Corriente máxima | 2 A |
| Tensión a 2 A | 0.2 V |
| Potencia a 2 A | 0.4 W |
| Potencia recomendada del resistor | 1 W mínimo, 2 W preferible |
| Caída de tensión | 0.2 V |
| Rango ADC usado | 0.2 V / 3.3 V ≈ 6.1% |
| LSB ideal del ADC | 3.3 V / 4096 ≈ 0.806 mV |
| Resolución ideal en corriente | 0.806 mV / 0.1 Ω ≈ 8.1 mA |

Con un shunt de 0.1 Ω, el sistema tendría una resolución ideal aproximada de **8 mA por cuenta de ADC**. En la práctica, por ruido y por la calidad del ADC, la resolución real puede ser menor, pero para medir consumo de motores puede ser suficiente.

## 4. Protección del Flipper Zero

Usted indica que no necesita protección porque la fuente es regulada y no pasará de 2 A. Desde el punto de vista de corriente, eso es correcto. Sin embargo, el pin ADC del Flipper Zero no se daña principalmente por corriente, sino por **tensión**.

Con un shunt de 0.1 Ω y 2 A máximos:

```text
Vshunt = 2 A × 0.1 Ω = 0.2 V
```

Eso está muy por debajo de 3.3 V, por lo que en condiciones normales el ADC estaría seguro.

Aun así, hay razones por las que normalmente se recomienda una protección mínima:

1. **Transitorios del motor**  
   Aunque la fuente sea regulada, los drivers de motores paso a paso pueden generar picos, ruido o rebotes.

2. **Inductancia del cableado**  
   Cables largos pueden introducir picos de tensión.

3. **Errores de conexión**  
   Si el cable de medición se conecta accidentalmente a otro punto, el pin ADC podría recibir más de 3.3 V.

4. **Descargas electrostáticas**  
   El hardware queda más robusto con una resistencia serie y capacidad de filtrado.

5. **Posible corriente negativa**  
   Si el motor o el driver pueden regenerar energía, podría aparecer una tensión negativa momentánea en el shunt. El ADC no acepta tensiones negativas.

Por tanto, aunque usted tenga un entorno controlado, la recomendación mínima sería:

```text
Shunt -> resistencia serie pequeña -> pin ADC
Pin ADC -> condensador de 100 nF a GND
```

Por ejemplo:

```text
Shunt+ ---- 100 Ω a 1 kΩ ---- GPIO ADC
                                 |
                               100 nF
                                 |
                                GND
```

Si desea máxima simplicidad y confía plenamente en el montaje, puede omitir los diodos de protección. Pero la resistencia serie y el condensador son baratos, simples y mejoran mucho la inmunidad al ruido.

## 6. Importante: ubicación del shunt y masa

El shunt debe colocarse preferiblemente en el **retorno**, es decir, en el lado negativo de la fuente principal.

### Correcto para medición directa

```text
Fuente +12 V -> montura
Montura GND  -> shunt -> fuente GND
```

El Flipper Zero debe medir la diferencia de tensión en el shunt. Como el ADC del Flipper no es diferencial, la referencia debe ser el lado negativo del shunt.

Por tanto:

```text
Flipper GND -> lado de fuente GND, es decir, SHUNT-
ADC input   -> lado de montura, es decir, SHUNT+
```

### Precaución con la masa del PC y del conversor serie

Si el conversor serie está alimentado desde el PC y conectado a la montura, puede haber una masa común adicional. Debe evitar que esa masa cree un camino alternativo alrededor del shunt.

En otras palabras: si la masa del conversor serie se conecta al lado de la montura, mientras que el Flipper Zero se conecta al lado de la fuente, puede existir una pequeña diferencia de masa y parte de corriente podría circular por rutas no deseadas.

En un sistema sencillo normalmente no es un problema grave si la caída del shunt es pequeña, por ejemplo 0.1–0.2 V. Pero debe verificarlo.

Recomendación práctica:

```text
Conectar todas las masas en un único punto cuando sea posible.
Verificar que el conversor serie y el Flipper Zero compartan una referencia compatible.
Si hay problemas, usar un conversor serie aislado o una medición diferencial.
```

## 7. Con un solo shunt en la fuente principal

Si el shunt está en la alimentación principal de la montura, la corriente medida será la corriente total consumida por la montura, no necesariamente solo la del eje en movimiento.

Esto incluye:

- Electrónica de control.
- Drivers de motor.
- Corriente de mantenimiento de los motores, si está activa.
- Corriente del eje que se está moviendo.

Si solo se mueve un eje a la vez, la variación dinámica estará dominada por ese eje, pero puede haber una corriente base constante.

Por ejemplo:

```text
Corriente medida = corriente base + corriente del eje en movimiento
```

Si usted quiere analizar solo la componente asociada al movimiento, puede hacer una de estas dos cosas:

### Opción A: Registrar una línea base

Antes de iniciar el movimiento, medir la corriente durante unos segundos con la montura en el mismo estado eléctrico.

Luego:

```text
corriente_corregida = corriente_medida - corriente_base
```

### Opción B: Analizar la componente variable

Para FFT o análisis de variaciones periódicas, la componente DC puede eliminarse. Esto es común en análisis espectral.

```text
corriente_ac = corriente_medida - media(corriente_medida)
```

Si necesita la corriente absoluta de un solo eje, entonces un shunt en la alimentación general no es suficiente. En ese caso convendría colocar el shunt específicamente en la alimentación del eje seleccionado.

Pero si solo se mueve un eje y el objetivo es observar el comportamiento durante la rotación, el shunt en la fuente principal puede ser válido.

## 8. ¿Pueden funcionar BLE y ADC simultáneamente en el Flipper Zero?

Sí, **en principio pueden funcionar simultáneamente**.

El hardware del Flipper Zero puede manejar BLE mientras se usan otros periféricos, incluyendo ADC, siempre que la aplicación esté correctamente diseñada.

Sin embargo, hay matices importantes.

---

### 8.1 No deben hacerse en un bucle bloqueante

Si el firmware hace algo como:

```c
leer_ADC();
enviar_BLE();
esperar_confirmación_BLE();
```

entonces BLE puede bloquear el muestreo.

La forma correcta es:

```text
ADC muestreado por temporizador
Muestras guardadas en buffer
BLE transmite cuando puede
```

---

### 8.2 Es preferible usar temporizador y buffer

La arquitectura recomendada es:

```text
Timer hardware -> dispara conversión ADC
ADC           -> genera muestra
Muestra       -> se guarda en FIFO
BLE           -> envía paquetes desde el FIFO
```

Así, aunque BLE tenga pequeñas interrupciones, la toma de muestras puede continuar.

---

### 8.3 La tasa de muestreo fiable depende de BLE

BLE no tiene la misma determinación que una conexión USB serial.

Para tasas bajas o moderadas, por ejemplo:

```text
1 Hz a 100 Hz
```

BLE suele ser suficiente si el firmware está bien implementado.

Para tasas mayores:

```text
500 Hz o 1000 Hz
```

puede funcionar, pero dependerá de:

- la implementación del firmware,
- la conexión BLE,
- el intervalo de conexión,
- el tamaño de los paquetes,
- el sistema operativo del PC,
- la distancia y calidad de radio.

En cualquier caso, el firmware debe usar números de secuencia para detectar pérdidas:

```text
paquete 100
paquete 101
paquete 102
paquete 104   <- falta 103
```

Así el software puede saber si se perdió alguna muestra.

---

### 8.4 El timestamp debe generarse en el Flipper

Este punto es clave.

Aunque BLE introduzca latencia, la muestra debe llevar un timestamp tomado en el momento de la adquisición ADC, no en el momento en que llega al PC.

Flujo correcto:

```text
ADC sample -> timestamp Flipper -> buffer -> BLE -> PC
```

En el PC:

```text
tiempo recibo = t_pc_rx
tiempo real muestra = t_flipper + offset de sincronización
```

Por tanto, la latencia BLE afecta a cuándo llega el dato, pero no necesariamente a qué instante físico representa, siempre que el timestamp se haya tomado correctamente en el Flipper.

## 1. Rango del ADC del Flipper Zero

No puedo abrir una página web en vivo desde aquí, pero según la documentación conocida del hardware del Flipper Zero y del microcontrolador STM32WB55:

- Los GPIO trabajan con lógica de **3.3 V**.
- El ADC depende de `VREF+` / `VDDA`.
- En muchas implementaciones, `VREF` es aproximadamente **3.3 V**.
- Algunas aplicaciones o configuraciones muestran rangos prudenciales de **2.0 V** o **2.5 V** para dejar margen de seguridad.

Por tanto, para diseño conservador, asumiré que usted quiere mantener la tensión medida por debajo de **2.0 V**. Si luego confirma que el ADC puede llegar a 2.5 V o 3.3 V, tendrá margen adicional, pero la limitación principal seguirá siendo la potencia de las resistencias.

## 2. Requisito teórico para obtener 1 mA de resolución

Para un ADC de 12 bits:

```text
LSB = Vref / 4096
```

La resolución en corriente depende de la resistencia shunt:

```text
I_LSB = Vref / (4096 × Rshunt)
```

Para obtener aproximadamente **1 mA por cuenta de ADC**, se necesita:

| Rango ADC efectivo | Rshunt mínima para 1 mA | Potencia con 2.5 A |
|---:|---:|---:|
| 2.0 V | 0.488 Ω | 3.05 W |
| 2.5 V | 0.610 Ω | 3.81 W |
| 3.3 V | 0.806 Ω | 5.04 W |

Es decir, para acercarse de verdad a 1 mA con 2.5 A, necesitaría aproximadamente:

```text
Rshunt entre 0.5 Ω y 0.8 Ω
```

y una disipación total de varios vatios.

Con sus resistencias, todas de **1 W** excepto las de 120 kΩ, no es posible construir de forma segura y continua un shunt de 0.5–0.8 Ω sin superar la potencia de algún elemento, salvo configuraciones extremas o de muy corta duración.

Aun así, se puede construir una red que aproveche bastante el rango disponible.

# 6. Sobre la precisión de 1 mA

Con estas configuraciones, la resolución ideal aproximada es:

| Configuración | Rtotal | V a 2.5 A | LSB con ADC 3.3 V | LSB con ADC 2.0 V |
|---|---:|---:|---:|---:|

| Recomendada | 0.406 Ω | 1.02 V | 2.0 mA | 1.2 mA |
| Máxima razonable | 0.420 Ω | 1.05 V | 1.9 mA | 1.16 mA |
| Simple 0.44 Ω, solo picos | 0.44 Ω | 1.10 V | 1.8 mA | 1.1 mA |
| Solo 0.65 Ω, solo picos | 0.65 Ω | 1.63 V | 1.24 mA | 0.75 mA |

Por tanto:

```text
Con sus resistencias y sin amplificador, 1 mA exacto no está garantizado.
```

Puede acercarse mediante:

- calibración precisa,
- promedio de muestras,
- filtrado,
- estabilidad térmica,
- bajo ruido eléctrico.

Pero la resolución física ideal no será necesariamente 1 mA, salvo que el ADC tenga una referencia más baja o se use amplificación.

Para lograr 1 mA reales de forma robusta, necesitaría una de estas opciones:

1. Un shunt de mayor resistencia y mayor potencia, por ejemplo:
   ```text
   0.5 Ω a 0.8 Ω, varios vatios, baja deriva térmica
   ```

2. Más resistencias de baja resistencia para distribuir potencia.

3. Un amplificador de corriente o un sensor de corriente dedicado.

# 7. Cómo conectar la red al Flipper Zero

La red debe colocarse preferiblemente en el retorno negativo, es decir, en el lado de baja tensión.

Para la configuración recomendada de 0.406 Ω:

```text
Fuente +12 V
   |
   v

   |
Retorno de corriente
   |
MOUNT_GND o--+--[0.17]--[0.17]--[0.10]--+--o SUPPLY_GND
             |                           |
             +------[0.65]--[4.7]--------+
             |                           |
             +---------------------------+
   |
Retorno a fuente GND
```

Conexión al Flipper:

```text
Flipper GND  -> terminal SUPPLY_GND del shunt
Flipper ADC  -> terminal MOUNT_GND del shunt, preferiblemente mediante 1 kΩ
```

Protección/filtro recomendado:

```text
MOUNT_GND ----[1 kΩ]----+---- GPIO ADC Flipper
                        |
                      100 nF
                        |
                     GND Flipper
```

Si no tiene condensador, use al menos la resistencia serie de **1 kΩ**. Si puede añadir un condensador de **100 nF**, mucho mejor.

La resistencia de 1 kΩ no debe ir en el camino principal de corriente del motor. Debe ir solo hacia el pin ADC.

Las resistencias de 120 kΩ no son útiles para el shunt. Podrían usarse como pull-down de muy alta impedancia en el pin ADC, pero no es necesario.

# 8. Calibración imprescindible

Con esta red, la calibración es obligatoria si quiere acercarse a 1 mA.

Debe calibrar:

1. Cero de corriente.
2. Ganancia, es decir, la relación entre lectura ADC y corriente real.
3. Offset térmico, si la medida es prolongada.

Método recomendado:

```text
1. Inyectar una corriente conocida, por ejemplo 1.0 A o 2.0 A.
2. Medir la tensión real en el shunt con un multímetro.
3. Comparar con la lectura del ADC.
4. Calcular el factor de conversión.
```

Para la configuración de 0.406 Ω, por ejemplo:

```text
A 1.0 A:
Vshunt esperado = 1.0 × 0.406 = 0.406 V

A 2.0 A:
Vshunt esperado = 2.0 × 0.406 = 0.812 V

A 2.5 A:
Vshunt esperado = 2.5 × 0.406 = 1.015 V
```

Si el valor real difiere, corrija en software.

```python
# protocol.py

MAGIC = 0xA5

# Commands from PC to Flipper
CMD_GET_INFO = 0x01
CMD_SET_RATE = 0x02
CMD_START = 0x03
CMD_STOP = 0x04

DATA_SAMPLES = 0x90


def crc8(data: bytes) -> int:
    """
    Simple CRC-8 with polynomial 0x07.
    """
    crc = 0x00
    for byte in data:
        crc ^= byte
        for _ in range(8):
            if crc & 0x80:
                crc = ((crc << 1) ^ 0x07) & 0xFF
            else:
                crc = (crc << 1) & 0xFF
    return crc


def build_frame(packet_type: int, payload: bytes = b"") -> bytes:
    """
    Frame format:

        MAGIC | LEN | TYPE | PAYLOAD | CRC8

    CRC is computed over TYPE + PAYLOAD.
    """
    body = bytes([packet_type]) + payload
    crc = crc8(body)
    return bytes([MAGIC, len(payload)]) + body + bytes([crc])


class FrameParser:
    """
    Reassembles binary frames from a BLE byte stream.
    """

    def __init__(self):
        self.buffer = bytearray()

    def feed(self, data: bytes):
        self.buffer.extend(data)
        frames = []

        while True:
            magic_index = self.buffer.find(bytes([MAGIC]))

            if magic_index < 0:
                self.buffer.clear()
                break

            if magic_index > 0:
                self.buffer = self.buffer[magic_index:]

            if len(self.buffer) < 3:
                break

            payload_len = self.buffer[1]
            total_len = 3 + payload_len + 1

            if len(self.buffer) < total_len:
                break

            body = self.buffer[2:2 + 1 + payload_len]
            received_crc = self.buffer[2 + 1 + payload_len]
            expected_crc = crc8(body)

            if received_crc == expected_crc:
                packet_type = body[0]
                payload = bytes(body[1:])
                frames.append((packet_type, payload))
                self.buffer = self.buffer[total_len:]
            else:
                # Resynchronize after a bad CRC.
                self.buffer = self.buffer[1:]

        return frames
```

```python
# flipper_client.py

import asyncio
import queue
import statistics
import struct
import time

from bleak import BleakClient

from config import CURRENT_PER_COUNT
from protocol import (
    CMD_SET_RATE,
    CMD_START,
    CMD_STOP,
    CMD_SYNC_REQ,
    RESP_SYNC,
    DATA_SAMPLES,
    FrameParser,
    build_frame,
)

# Nordic UART Service UUIDs.
NUS_SERVICE_UUID = "6E400001-B5A3-F393-E0A9-E50E24DCCA9E"
NUS_RX_UUID = "6E400002-B5A3-F393-E0A9-E50E24DCCA9E"
NUS_TX_UUID = "6E400003-B5A3-F393-E0A9-E50E24DCCA9E"


class FlipperClient:
    """
    Bluetooth LE client for the Flipper Zero current logger.
    """

    def __init__(self, address: str):
        self.address = address
        self.client = BleakClient(address, timeout=20.0)
        self.parser = FrameParser()

        # Async queue for control responses, e.g. synchronization responses.
        self.control_queue = asyncio.Queue()

        # Thread-safe queue for decoded current samples.
        self.sample_queue = queue.Queue()

        self.connected = False

        # Clock relationship:
        # PC_monotonic_ns = Flipper_time_ns + offset_ns
        self.offset_ns = 0
        self.offset_uncertainty_ns = 0
        self.last_rtt_ms = 0.0

    async def connect(self):
        await self.client.connect()
        await self.client.start_notify(NUS_TX_UUID, self._notification_handler)
        self.connected = True

    async def disconnect(self):
        if self.client.is_connected:
            await self.client.disconnect()
        self.connected = False

    async def send_frame(self, packet_type: int, payload: bytes = b""):
        frame = build_frame(packet_type, payload)
        await self.client.write_gatt_char(NUS_RX_UUID, frame, response=False)

    async def set_sample_rate(self, rate_hz: int):
        payload = struct.pack("<H", int(rate_hz))
        await self.send_frame(CMD_SET_RATE, payload)

    async def start_sampling(self):
        await self.send_frame(CMD_START)

    async def stop_sampling(self):
        await self.send_frame(CMD_STOP)

    def _notification_handler(self, sender, data: bytearray):
        """
        BLE notification callback.
        """
        frames = self.parser.feed(bytes(data))

        for packet_type, payload in frames:
            if packet_type == RESP_SYNC:
                # Store PC receive time as early as possible.
                self.control_queue.put_nowait((time.monotonic_ns(), payload))

            elif packet_type == DATA_SAMPLES:
                self._decode_sample_packet(payload)

    def _decode_sample_packet(self, payload: bytes):
        """
        DATA_SAMPLES payload format:

            uint32 packet_sequence
            uint8  flags
            uint8  sample_count
            uint64 first_flipper_time_us
            uint16 sample_interval_us
            uint16 adc_samples[sample_count]
        """
        header_size = 16

        if len(payload) < header_size:
            return

        seq, flags, count, first_time_us, interval_us = struct.unpack(
            "<IBBQH",
            payload[:header_size]
        )

        expected_size = header_size + 2 * count

        if len(payload) < expected_size:
            return

        adc_counts = struct.unpack(
            "<" + "H" * count,
            payload[header_size:expected_size]
        )

        base_time_ns = first_time_us * 1000 + self.offset_ns
        delta_ns = interval_us * 1000

        for i, adc_count in enumerate(adc_counts):
            timestamp_ns = base_time_ns + i * delta_ns
            current_a = adc_count * CURRENT_PER_COUNT
            self.sample_queue.put((timestamp_ns, adc_count, current_a, seq, flags))

    async def sync_clocks(self, sample_count: int = 30):
        """
        Performs PC-Flipper clock synchronization.

        The PC sends CMD_SYNC_REQ containing its monotonic time.
        The Flipper returns its own timestamp.

        Offset estimate:

            offset = flipper_time_ns - midpoint_pc_time_ns
        """
        # Remove stale responses.
        while not self.control_queue.empty():
            self.control_queue.get_nowait()

        offsets = []
        rtts = []

        for _ in range(sample_count):
            t1 = time.monotonic_ns()
            payload = struct.pack("<Q", t1)

            await self.send_frame(CMD_SYNC_REQ, payload)

            try:
                t2, response_payload = await asyncio.wait_for(
                    self.control_queue.get(),
                    timeout=2.0
                )
            except asyncio.TimeoutError:
                continue

            if len(response_payload) < 16:
                continue

            pc_echo, flipper_time_us = struct.unpack(
                "<QQ",
                response_payload[:16]
            )

            rtt_ns = t2 - t1
            midpoint_ns = (t1 + t2) // 2
            offset_ns = flipper_time_us * 1000 - midpoint_ns

            rtts.append(rtt_ns)
            offsets.append(offset_ns)

            await asyncio.sleep(0.01)

        if not offsets:
            raise RuntimeError("Clock synchronization failed.")

        # Use the lowest 50% RTT samples to reduce latency asymmetry effects.
        paired = sorted(zip(rtts, offsets), key=lambda item: item[0])
        keep = max(5, len(paired) // 2)
        filtered_offsets = [offset for _, offset in paired[:keep]]
        filtered_rtts = [rtt for rtt, _ in paired[:keep]]

        self.offset_ns = int(statistics.median(filtered_offsets))

        if len(filtered_offsets) > 1:
            self.offset_uncertainty_ns = int(statistics.stdev(filtered_offsets))
        else:
            self.offset_uncertainty_ns = 5_000_000

        self.last_rtt_ms = statistics.median(filtered_rtts) / 1_000_000.0

        return (
            self.offset_ns,
            self.offset_uncertainty_ns,
            self.last_rtt_ms,
        )
```

```python
def circular_stats_deg(angles_deg):
    """
    Circular mean, circular standard deviation, and approximate circular
    standard error for angular data.
    """
    angles = np.asarray(angles_deg, dtype=float)
    angles = angles[~np.isnan(angles)]

    if angles.size == 0:
        return np.nan, np.nan, np.nan, 0

    rad = np.deg2rad(np.mod(angles, 360.0))

    c = np.mean(np.cos(rad))
    s = np.mean(np.sin(rad))
    r = np.hypot(c, s)

    mean_deg = np.rad2deg(np.arctan2(s, c)) % 360.0

    if r >= 1.0:
        std_deg = 0.0
    else:
        std_deg = np.rad2deg(np.sqrt(-2.0 * np.log(r)))

    n = angles.size

    if n > 1 and r > 0.0:
        se_deg = np.rad2deg(np.sqrt(max(0.0, (1.0 - r) / (n * r))))
    else:
        se_deg = 0.0

    return mean_deg, std_deg, se_deg, n


def save_raw_csv(samples, base_path: str):
    """
    Saves the authoritative raw long CSV and an optional wide CSV for
    multi-revolution inspection.

    samples: list of dict with keys:
        timestamp_ns
        revolution_index
        angle_rel_deg
        current_A
    """
    if not samples:
        return

    # Save long raw CSV.
    with open(base_path, "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=RAW_FIELDS)
        writer.writeheader()

        for sample in samples:
            writer.writerow({
                "timestamp_ns": int(sample["timestamp_ns"]),
                "revolution_index": int(sample["revolution_index"]),
                "angle_rel_deg": float(sample["angle_rel_deg"]),
                "current_A": float(sample["current_A"]),
            })

    revolutions = sorted({int(s["revolution_index"]) for s in samples})

    if len(revolutions) <= 1:
        return

    # Save wide raw CSV as a derived view.
    base, _ = os.path.splitext(base_path)
    wide_path = base + ".wide.csv"

    rev_data = {
        rev: [s for s in samples if int(s["revolution_index"]) == rev]
        for rev in revolutions
    }

    max_len = max(len(items) for items in rev_data.values())

    headers = ["sample_index"]

    for rev in revolutions:
        headers.extend([
            f"timestamp_rev_{rev:02d}_ns",
            f"angle_rev_{rev:02d}_deg",
            f"current_rev_{rev:02d}_A",
        ])

    headers.extend([
        "average_angle_deg",
        "angle_std_deg",
        "average_current_A",
        "current_std_A",
    ])

    with open(wide_path, "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=headers)
        writer.writeheader()

        for i in range(max_len):
            row = {"sample_index": i}
            angles = []
            currents = []

            for rev in revolutions:
                items = rev_data[rev]

                if i < len(items):
                    sample = items[i]
                    row[f"timestamp_rev_{rev:02d}_ns"] = int(sample["timestamp_ns"])
                    row[f"angle_rev_{rev:02d}_deg"] = float(sample["angle_rel_deg"])
                    row[f"current_rev_{rev:02d}_A"] = float(sample["current_A"])

                    angles.append(float(sample["angle_rel_deg"]))
                    currents.append(float(sample["current_A"]))
                else:
                    row[f"timestamp_rev_{rev:02d}_ns"] = ""
                    row[f"angle_rev_{rev:02d}_deg"] = ""
                    row[f"current_rev_{rev:02d}_A"] = ""

            if angles:
                mean_angle, std_angle, _, _ = circular_stats_deg(angles)
                row["average_angle_deg"] = mean_angle
                row["angle_std_deg"] = std_angle
                row["average_current_A"] = float(np.mean(currents))
                row["current_std_A"] = float(np.std(currents, ddof=1)) if len(currents) > 1 else 0.0
            else:
                row["average_angle_deg"] = ""
                row["angle_std_deg"] = ""
                row["average_current_A"] = ""
                row["current_std_A"] = ""

            writer.writerow(row)

def _block_average_rows(
    timestamps_ns,
    angles_deg,
    currents_a,
    avg_factor: int,
    revolution_index: int,
    sync_uncertainty_ns: float,
):
    rows = []
    n = len(timestamps_ns)

    for block_index, start in enumerate(range(0, n, avg_factor)):
        end = min(start + avg_factor, n)

        ts = timestamps_ns[start:end]
        an = angles_deg[start:end]
        cu = currents_a[start:end]

        count = len(ts)

        if count == 0:
            continue

        mean_timestamp = int(np.mean(ts))

        if count > 1:
            duration_ns = float(ts[-1] - ts[0])
            ts_std_ns = float(np.std(ts, ddof=1))
            timestamp_uncertainty = float(np.sqrt(
                sync_uncertainty_ns ** 2 +
                (duration_ns / np.sqrt(12.0)) ** 2 +
                (ts_std_ns / np.sqrt(count)) ** 2
            ))
        else:
            timestamp_uncertainty = float(sync_uncertainty_ns)

        angle_mean, angle_std, angle_se, _ = circular_stats_deg(an)

        current_mean = float(np.mean(cu))

        if count > 1:
            current_std = float(np.std(cu, ddof=1))
            current_uncertainty = current_std / np.sqrt(count)
        else:
            current_std = 0.0
            current_uncertainty = 0.0

        rows.append({
            "record_type": "revolution",
            "revolution_index": int(revolution_index),
            "block_index": int(block_index),
            "phase_deg": float(angle_mean),
            "mean_timestamp_ns": int(mean_timestamp),
            "timestamp_uncertainty_ns": float(timestamp_uncertainty),
            "angle_mean_deg": float(angle_mean),
            "angle_std_deg": float(angle_std),
            "angle_uncertainty_deg": float(angle_se),
            "current_mean_A": float(current_mean),
            "current_std_A": float(current_std),
            "current_uncertainty_A": float(current_uncertainty),
            "sample_count": int(count),
        })

    return rows


def process_raw_file(raw_path: str, avg_factor: int, sync_uncertainty_ns: float = 0.0):
    """
    Generates processed rows from a raw long CSV.
    """
    data = load_raw_csv(raw_path)

    timestamps = data["timestamp_ns"]
    revolutions = data["revolution_index"]
    angles = data["angle_rel_deg"]
    currents = data["current_A"]

    order = np.argsort(timestamps)

    timestamps = timestamps[order]
    revolutions = revolutions[order]
    angles = angles[order]
    currents = currents[order]

    unique_revolutions = sorted(set(revolutions.tolist()))

    revolution_rows = []

    for rev in unique_revolutions:
        mask = revolutions == rev

        rev_rows = _block_average_rows(
            timestamps[mask],
            angles[mask],
            currents[mask],
            avg_factor,
            rev,
            sync_uncertainty_ns,
        )

        revolution_rows.extend(rev_rows)

    average_rows = []

    block_indices = sorted({row["block_index"] for row in revolution_rows})

    for block_index in block_indices:
        group = [
            row for row in revolution_rows
            if row["block_index"] == block_index
        ]

        if not group:
            continue

        n = len(group)

        mean_timestamp = int(np.mean([row["mean_timestamp_ns"] for row in group]))

        timestamp_uncertainty = float(np.sqrt(
            sum(row["timestamp_uncertainty_ns"] ** 2 for row in group)
        )) / n

        angle_values = [row["angle_mean_deg"] for row in group]
        angle_mean, angle_std, angle_se, _ = circular_stats_deg(angle_values)

        angle_uncertainty = float(np.sqrt(
            sum(row["angle_uncertainty_deg"] ** 2 for row in group)
        )) / n

        current_values = [row["current_mean_A"] for row in group]
        current_mean = float(np.mean(current_values))
        current_std = float(np.std(current_values, ddof=1)) if n > 1 else 0.0

        current_uncertainty = float(np.sqrt(
            sum(row["current_uncertainty_A"] ** 2 for row in group)
        )) / n

        sample_count = sum(row["sample_count"] for row in group)

        average_rows.append({
            "record_type": "average",
            "revolution_index": 0,
            "block_index": int(block_index),
            "phase_deg": float(angle_mean),
            "mean_timestamp_ns": int(mean_timestamp),
            "timestamp_uncertainty_ns": float(timestamp_uncertainty),
            "angle_mean_deg": float(angle_mean),
            "angle_std_deg": float(angle_std),
            "angle_uncertainty_deg": float(angle_uncertainty),
            "current_mean_A": float(current_mean),
            "current_std_A": float(current_std),
            "current_uncertainty_A": float(current_uncertainty),
            "sample_count": int(sample_count),
        })

    return revolution_rows + average_rows

def fft_from_processed_csv(processed_path: str):
    """
    Computes a real FFT from the averaged processed current data.

    Returns the five dominant frequency peaks as:

        [(frequency_hz, period_s), ...]
    """
    rows = read_processed_csv(processed_path)

    avg_rows = [
        row for row in rows
        if row["record_type"] == "average"
    ]

    if len(avg_rows) < 8:
        return []

    avg_rows.sort(key=lambda row: row["mean_timestamp_ns"])

    times_ns = np.asarray([row["mean_timestamp_ns"] for row in avg_rows], dtype=float)
    currents = np.asarray([row["current_mean_A"] for row in avg_rows], dtype=float)

    dt_ns = np.median(np.diff(times_ns))

    if dt_ns <= 0:
        return []

    dt_s = dt_ns * 1e-9
    t_s = (times_ns - times_ns[0]) * 1e-9

    uniform_t = np.arange(t_s[0], t_s[-1], dt_s)

    if len(uniform_t) < 8:
        return []

    y = np.interp(uniform_t, t_s, currents)
    y = y - np.mean(y)

    window = hann(len(y))
    spectrum = np.abs(rfft(y * window)) * 2.0 / np.sum(window)
    freqs = rfftfreq(len(y), d=dt_s)

    # Exclude DC.
    mask = freqs > 0.02
    freqs_masked = freqs[mask]
    spectrum_masked = spectrum[mask]

    if len(spectrum_masked) < 5:
        return []

    threshold = np.median(spectrum_masked) * 3.0

    peaks, _ = find_peaks(
        spectrum_masked,
        height=threshold,
        distance=3,
    )

    if len(peaks) == 0:
        # If no clear peaks are found, take the largest non-DC bins.
        peaks = np.argsort(spectrum_masked)[::-1][:5]

    amplitudes = spectrum_masked[peaks]
    order = np.argsort(amplitudes)[::-1][:5]

    result = []

    for idx in peaks[order]:
        freq = float(freqs_masked[idx])

        if freq <= 0:
            continue

        period = 1.0 / freq
        result.append((freq, period))

    return result
```

```python
                while not self.flipper.sample_queue.empty():
                    timestamp_ns, adc_count, current_a, seq, flags = (

                raw_angle = self.mount.get_position_deg()

                    delta -= 360.0
                elif delta < -180.0:
                    delta += 360.0

                last_raw_angle = raw_angle

                angle_log.append((
                    time.monotonic_ns(),
                    raw_angle,
                    unwrapped_angle,
                ))

                while (
                    completed_revolutions < requested_revolutions and
                    unwrapped_angle >= start_unwrapped + (completed_revolutions + 1) * 360.0

                    self.flipper.sample_queue.get()
                )

            revolution_indices = np.clip(revolution_indices, 1, requested_revolutions)

            angle_rel = np.mod(relative_to_start, 360.0)
```

```c
static uint8_t crc8(const uint8_t *data, uint16_t len)
{
    uint8_t crc = 0x00;

    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];

        for (uint8_t bit = 0; bit < 8; bit++) {
            if (crc & 0x80) {
                crc = (uint8_t)((crc << 1) ^ 0x07);
            } else {
                crc = (uint8_t)(crc << 1);
            }
        }
    }

    return crc;
}

static void dwt_cycle_counter_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CYCCNT = 0;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
}

static uint32_t micros(void)
{
    return DWT->CYCCNT / (SystemCoreClock / 1000000U);
}

static uint16_t fifo_count(void)
{
    return (uint16_t)((fifo_head - fifo_tail) % FIFO_SIZE);
}

static bool fifo_push(const sample_t *sample)
{
    uint16_t next_head = (uint16_t)((fifo_head + 1) % FIFO_SIZE);

    if (next_head == fifo_tail) {
        return false;
    }

    sample_fifo[fifo_head] = *sample;
    fifo_head = next_head;

    return true;
}

static bool fifo_pop(sample_t *sample)
{
    if (fifo_head == fifo_tail) {
        return false;
    }

    *sample = sample_fifo[fifo_tail];
    fifo_tail = (uint16_t)((fifo_tail + 1) % FIFO_SIZE);

    return true;
}

static void send_frame(uint8_t packet_type, const uint8_t *payload, uint8_t len)
{
    uint8_t buffer[260];

    if (len > 240) {
        return;
    }

    buffer[0] = MAGIC;
    buffer[1] = len;
    buffer[2] = packet_type;

    if (len > 0) {
        memcpy(&buffer[3], payload, len);
    }

    buffer[3 + len] = crc8(&buffer[2], (uint16_t)(len + 1));

    ble_nus_send(buffer, (uint16_t)(4 + len));
}

static void handle_sync_request(const uint8_t *payload, uint8_t len)
{
    if (len < 8) {
        return;
    }

    uint64_t pc_echo;
    memcpy(&pc_echo, payload, sizeof(pc_echo));

    uint64_t flipper_time_us = micros();

    uint8_t response[16];
    memcpy(&response[0], &pc_echo, sizeof(pc_echo));
    memcpy(&response[8], &flipper_time_us, sizeof(flipper_time_us));

    send_frame(RESP_SYNC, response, sizeof(response));
}

{
    if (len < 2) {
        return;
    }

    memcpy(&rate_hz, payload, sizeof(rate_hz));

    if (rate_hz < 1) {
        rate_hz = 1;

    if (rate_hz > 1000) {

    sample_rate_hz = rate_hz;

}

static void handle_command_frame(uint8_t packet_type, const uint8_t *payload, uint8_t len)
{
    switch (packet_type) {
        case CMD_SYNC_REQ:
            handle_sync_request(payload, len);

static void parse_received_bytes(const uint8_t *data, uint16_t len)
{
    /*
     * Simplified parser.
     * For production firmware, use a robust ring-buffer frame parser.
     */
    static uint8_t rx_buffer[512];
    static uint16_t rx_len = 0;

    for (uint16_t i = 0; i < len; i++) {
        if (rx_len < sizeof(rx_buffer)) {
            rx_buffer[rx_len++] = data[i];
        }
    }

    while (rx_len >= 4) {
        if (rx_buffer[0] != MAGIC) {
            memmove(rx_buffer, rx_buffer + 1, rx_len - 1);
            rx_len--;
            continue;
        }

        uint8_t payload_len = rx_buffer[1];
        uint16_t frame_len = (uint16_t)(4 + payload_len);

        if (rx_len < frame_len) {
            break;
        }

        uint8_t packet_type = rx_buffer[2];
        const uint8_t *payload = &rx_buffer[3];
        uint8_t received_crc = rx_buffer[3 + payload_len];
        uint8_t expected_crc = crc8(&rx_buffer[2], (uint16_t)(payload_len + 1));

        if (received_crc == expected_crc) {
            handle_command_frame(packet_type, payload, payload_len);
        }

        memmove(rx_buffer, rx_buffer + frame_len, rx_len - frame_len);
        rx_len = (uint16_t)(rx_len - frame_len);
    }
}

static void send_sample_batch(void)
{
    if (fifo_count() < MAX_BATCH_SAMPLES) {
        return;
    }

    sample_t batch[MAX_BATCH_SAMPLES];
    uint8_t count = 0;

    while (count < MAX_BATCH_SAMPLES && fifo_pop(&batch[count])) {
        count++;
    }

    if (count == 0) {
        return;
    }

    packet_sequence++;

    uint8_t payload[128];
    uint16_t offset = 0;

    uint8_t flags = 0;
    uint64_t first_timestamp_us = batch[0].timestamp_us;
    uint16_t interval_us = (uint16_t)(1000000U / sample_rate_hz);

    memcpy(&payload[offset], &packet_sequence, sizeof(packet_sequence));
    offset += sizeof(packet_sequence);

    payload[offset++] = flags;
    payload[offset++] = count;

    memcpy(&payload[offset], &first_timestamp_us, sizeof(first_timestamp_us));
    offset += sizeof(first_timestamp_us);

    memcpy(&payload[offset], &interval_us, sizeof(interval_us));
    offset += sizeof(interval_us);

    for (uint8_t i = 0; i < count; i++) {
        memcpy(&payload[offset], &batch[i].adc_count, sizeof(uint16_t));
        offset += sizeof(uint16_t);
    }

    send_frame(DATA_SAMPLES, payload, (uint8_t)offset);
}
```

La conversión de corriente se realiza en Python usando:

```python
current_A = adc_count * CURRENT_PER_COUNT
```

donde:


para:

```text
Vref = 2.5 V
```

## 11.3 Calibración

Antes de mediciones precisas, calibre el sistema.

Procedimiento recomendado:

1. Con corriente cero, guarde el offset del ADC.
2. Inyecte una corriente conocida, por ejemplo 1.0 A.
3. Mida la tensión real en el shunt con un multímetro.
4. Compare con la lectura del ADC.
5. Ajuste `SHUNT_OHM` o `CURRENT_PER_COUNT` en `config.py`.

Para la Configuración A:

```text
A 1.0 A:
Vshunt esperado = 0.323 V

A 2.0 A:
Vshunt esperado = 0.646 V

A 2.5 A:
Vshunt esperado = 0.8075 V
```

Aunque use la Configuración A, se recomienda mantener una protección mínima en el pin ADC:

```text
Shunt+ ---- 1 kΩ ---- GPIO ADC
                       |
                     100 nF
                       |
                      GND
```

Si puede añadir diodos Schottky de protección a 3.3 V y a GND, mejor.

# 12. Flujo final del sistema

Con este código, el flujo operativo es:

1. El usuario selecciona el puerto de la montura.
2. Conecta la NEQ6 o usa la montura simulada.
3. Introduce la dirección BLE del Flipper Zero.
4. Conecta el Flipper.
5. Configura la tasa de muestreo.
6. Pulsa sincronización manual si desea verificar el offset.
7. Selecciona eje, velocidad y número de revoluciones.
8. Pulsa Start.
9. El sistema realiza sincronización automática.
10. El Flipper comienza a muestrear corriente.
11. La montura comienza a moverse.
12. El PC registra posición angular y muestras de corriente.
13. Al finalizar, se genera un CSV crudo con nombre basado en fecha/hora.
14. El usuario selecciona un factor de promedio.
15. El programa genera o reutiliza un CSV procesado.
16. Se actualizan:
    - gráfico polar,
    - gráfico cartesiano,
    - FFT,
    - estadísticas de corriente.

Esto cumple la relación fundamental solicitada:

```text
timestamp sincronizado ↔ posición angular ↔ corriente de motor
```

Sí. Con el protocolo **SynScan Serial Communication Protocol v3.3** que ha adjuntado, la NEQ6 puede integrarse directamente por puerto COM a través del conversor UART-USB.

Para una montura ecuatorial alemana NEQ6, la estrategia recomendada es:

- Usar **`z`** — *Get precise AZM-ALT* — para leer la posición de eje.
  - En monturas ecuatoriales, SynScan asocia:
    - `Azm` ↔ motor RA.
    - `Alt` ↔ motor DEC.
  - Esta posición es adecuada para medir una rotación mecánica relativa, incluso si la montura no está alineada.
- Usar comandos **`P` de slew variable** para mover RA o DEC a una velocidad definida en grados/segundo.
- Desactivar el tracking antes del slew y restaurarlo después.
- Detener el movimiento con comandos de parada y, de forma adicional, con `M` — *Cancel GOTO* — por seguridad.

```python
# mount.py

import threading
import time
from enum import Enum

import serial


class Axis(Enum):
    RA = 1
    DEC = 2


class MotionDirection(Enum):
    FORWARD = 1
    REVERSE = -1


class MountBase:
    """
    Abstract mount interface.
    """

    def __init__(self):
        self.connected = False
        self.running = False

    def connect(self):
        raise NotImplementedError

    def disconnect(self):
        raise NotImplementedError

    def set_speed_deg_s(self, speed_deg_s: float):
        raise NotImplementedError

    def start_motion(self, axis: Axis, direction: MotionDirection):
        raise NotImplementedError

    def stop_motion(self):
        raise NotImplementedError

    def get_position_deg(self) -> float:
        raise NotImplementedError


class SimulatedMount(MountBase):
    """

    """

    def __init__(self):

        self.speed_deg_s = 1.0
        self.axis = Axis.RA
        self.direction = MotionDirection.FORWARD
        self.start_time = None
        self.start_angle = 0.0
        self.angle = 0.0

    def connect(self):
        self.connected = True

    def disconnect(self):

        self.running = False

    def set_speed_deg_s(self, speed_deg_s: float):
        self.speed_deg_s = float(speed_deg_s)

    def start_motion(self, axis: Axis, direction: MotionDirection):
        self.axis = axis
        self.direction = direction
        self.running = True
        self.start_time = time.monotonic()
        self.start_angle = self.angle

    def stop_motion(self):
        self.running = False

    def get_position_deg(self) -> float:
        if self.running and self.start_time is not None:
            elapsed = time.monotonic() - self.start_time
            motion = self.direction.value * self.speed_deg_s * elapsed
            self.angle = (self.start_angle + motion) % 360.0

        return self.angle


class Neq6Serial(MountBase):
    """
    Sky-Watcher SynScan / NEQ6 serial driver.

    Implements the SynScan serial communication protocol version 3.3.

    Communication parameters:
        9600 baud
        8 data bits
        No parity
        1 stop bit

    Important implementation choices for NEQ6 current-consumption measurements:

    1. Position is read with the precise AZM-ALT command "z".
       For equatorial mounts:
           AZM corresponds to the RA motor axis.
           ALT corresponds to the DEC motor axis.

       This is preferred over RA/DEC sky coordinates because AZM/ALT axis
       positions are more appropriate for measuring mechanical rotation of
       a mount axis.

    2. Motion is performed with variable-rate P commands.
       The GUI speed is given in degrees per second.
       SynScan variable rate expects arcseconds per second encoded as:

           encoded_rate = rate_arcsec_per_s * 4

       split into high and low bytes.

    3. Tracking is disabled before slewing and restored after stopping.
       This avoids conflicts between the commanded slew and the internal
       tracking mode.
    """

    DEFAULT_BAUDRATE = 9600

    # Normal command timeout.
    RESPONSE_TIMEOUT_S = 1.0

    # The SynScan document warns that some commands may require up to 5 s
    # in worst-case scenarios. Position queries use this longer timeout.
    POSITION_TIMEOUT_S = 5.0

    # SynScan variable-rate encoding:
    # encoded = arcsec_per_s * 4, maximum 65535.
    # Therefore maximum variable speed is:
    # 65535 / 4 / 3600 = 4.5507 deg/s.
    MAX_VARIABLE_SPEED_DEG_S = 65535.0 / (4.0 * 3600.0)

    # SynScan motor axis codes used in P commands.
    AXIS_CODE_RA = 16      # Azm or RA
    AXIS_CODE_DEC = 17     # Alt or DEC

    # Direction/data bytes for variable-rate slew.
    DIRECTION_POSITIVE = 6
    DIRECTION_NEGATIVE = 7

    # Fixed-rate slew direction bytes.
    FIXED_DIRECTION_POSITIVE = 36
    FIXED_DIRECTION_NEGATIVE = 37

    # Tracking modes.
    TRACKING_OFF = 0
    TRACKING_ALT_AZ = 1
    TRACKING_EQUATORIAL = 2
    TRACKING_PEC = 3

    def __init__(self, port: str, baudrate: int = DEFAULT_BAUDRATE):
        super().__init__()

        self.port_name = port
        self.baudrate = baudrate

        # Low-level serial read slice timeout.
        self.serial_timeout = 0.05

        self.serial_port = None

        self.speed_deg_s = 1.0
        self.axis = Axis.RA
        self.direction = MotionDirection.FORWARD

        self.model = None
        self.firmware_version = None

        self._previous_tracking_mode = None
        self._lock = threading.RLock()

        # The SynScan protocol shown in the PDF does not require CR.
        # If a particular clone requires CR, this can be set to b"\r".
        self.command_terminator = b""

    # ------------------------------------------------------------------
    # Connection handling
    # ------------------------------------------------------------------

    def connect(self):
        with self._lock:
            self.serial_port = serial.Serial(
                port=self.port_name,
                baudrate=self.baudrate,
                bytesize=serial.EIGHTBITS,
                parity=serial.PARITY_NONE,
                stopbits=serial.STOPBITS_ONE,
                timeout=self.serial_timeout,
            )

            self.connected = True

            try:
                self._ping()
            except Exception:
                self.disconnect()
                raise

            try:
                self.firmware_version = self._get_firmware_version()
            except Exception:
                self.firmware_version = None

            try:
                self.model = self._get_model()
            except Exception:
                self.model = None

    def disconnect(self):
        with self._lock:
            try:
                if self.running:
                    self.stop_motion()
            except Exception:
                pass

            if self.serial_port and self.serial_port.is_open:
                self.serial_port.close()

            self.serial_port = None
            self.connected = False
            self.running = False

    # ------------------------------------------------------------------
    # Low-level serial protocol helpers
    # ------------------------------------------------------------------

    def _send_command(self, command: bytes, timeout: float = None) -> bytes:
        """
        Sends a SynScan command and waits for a response ending with '#'.

        Returns the response payload without the trailing '#'.
        """
        with self._lock:
            if self.serial_port is None or not self.serial_port.is_open:
                raise RuntimeError("Mount serial port is not open.")

            if timeout is None:
                timeout = self.RESPONSE_TIMEOUT_S

            # Discard any stale data before issuing a new command.
            self.serial_port.reset_input_buffer()

            self.serial_port.write(command + self.command_terminator)
            self.serial_port.flush()

            return self._read_response(timeout)

    def _read_response(self, timeout: float) -> bytes:
        """
        Reads bytes until '#'.

        The trailing '#' is removed.
        """
        deadline = time.monotonic() + timeout
        response = bytearray()

        while True:
            remaining = deadline - time.monotonic()

            if remaining <= 0:
                raise TimeoutError("Mount response timeout.")

            self.serial_port.timeout = min(self.serial_timeout, remaining)
            chunk = self.serial_port.read(1)

            if not chunk:
                continue

            if chunk == b"#":
                return bytes(response)

            response.extend(chunk)

            # Safety guard against malformed responses.
            if len(response) > 256:
                raise IOError("Mount response too long.")

    # ------------------------------------------------------------------
    # Basic identification and health commands
    # ------------------------------------------------------------------

    def _ping(self):
        """
        Echo command:

            PC sends: 'K' & chr(x)
            Mount replies: chr(x) & '#'
        """
        test_byte = 0x55
        response = self._send_command(
            b"K" + bytes([test_byte]),
            timeout=self.RESPONSE_TIMEOUT_S,
        )

        if len(response) != 1 or response[0] != test_byte:
            raise IOError("Mount echo test failed.")

    def _get_firmware_version(self) -> str:
        """
        Get Version command:

            PC sends: 'V'
            Mount replies with 6 ASCII hexadecimal digits followed by '#'.
        """
        response = self._send_command(b"V", timeout=self.RESPONSE_TIMEOUT_S)
        return response.decode("ascii", errors="ignore")

    def _get_model(self) -> int:
        """
        Get Model command:

            PC sends: 'm'
            Mount replies: chr(model) & '#'

        For EQ6 GOTO series, model should be 0.
        """
        response = self._send_command(b"m", timeout=self.RESPONSE_TIMEOUT_S)

        if len(response) < 1:
            raise IOError("Mount returned empty model response.")

        return int(response[0])

    # ------------------------------------------------------------------
    # Tracking commands
    # ------------------------------------------------------------------

    def _get_tracking_mode(self) -> int:
        """
        Get Tracking Mode command:

            PC sends: 't'
            Mount replies: chr(mode) & '#'
        """
        response = self._send_command(b"t", timeout=self.RESPONSE_TIMEOUT_S)

        if len(response) < 1:
            raise IOError("Mount returned empty tracking mode response.")

        return int(response[0])

    def _set_tracking_mode(self, mode: int):
        """
        Set Tracking Mode command:

            PC sends: 'T' & chr(mode)
            Mount replies: '#'
        """
        self._send_command(
            b"T" + bytes([mode & 0xFF]),
            timeout=self.RESPONSE_TIMEOUT_S,
        )

    def _disable_tracking_for_measurement(self):
        """
        Saves the current tracking mode once and switches tracking off.
        """
        if self._previous_tracking_mode is None:
            try:
                self._previous_tracking_mode = self._get_tracking_mode()
            except Exception:
                # If unknown, assume equatorial tracking for an NEQ6.
                self._previous_tracking_mode = self.TRACKING_EQUATORIAL

        try:
            self._set_tracking_mode(self.TRACKING_OFF)
        except Exception:
            # If disabling tracking fails, continue but do not leave a
            # stale saved state that could be restored incorrectly.
            self._previous_tracking_mode = None
            raise

    def _restore_tracking_after_measurement(self):
        """
        Restores the previously saved tracking mode.
        """
        if self._previous_tracking_mode is None:
            return

        try:
            self._set_tracking_mode(self._previous_tracking_mode)
        finally:
            self._previous_tracking_mode = None

    # ------------------------------------------------------------------
    # Position commands
    # ------------------------------------------------------------------

    def get_position_deg(self) -> float:
        """
        Returns the selected axis position in degrees, range [0, 360).

        For NEQ6 current-consumption measurements this uses precise AZM-ALT:

            'z'

        AZM is used for RA axis.
        ALT is used for DEC axis.
        """
        try:
            return self._get_precise_axis_position_deg(self.axis)
        except Exception:
            # Fallback to standard AZM-ALT if precise command is not accepted.
            return self._get_standard_axis_position_deg(self.axis)

    def _get_precise_axis_position_deg(self, axis: Axis) -> float:
        """
        Get precise AZM-ALT:

            PC sends: 'z'
            Mount replies, for example:
                "12AB0500,40000500#"

        The upper 24 bits are used.
        The last two hexadecimal digits are ignored.
        """
        response = self._send_command(b"z", timeout=self.POSITION_TIMEOUT_S)
        text = response.decode("ascii", errors="ignore")

        parts = text.split(",")

        if len(parts) != 2:
            raise ValueError("Invalid precise AZM-ALT response.")

        if axis == Axis.RA:
            hex_text = parts[0].strip()
        else:
            hex_text = parts[1].strip()

        if not hex_text:
            raise ValueError("Empty axis position field.")

        # Use upper 24 bits. If the string is longer than 6 hex digits,
        # discard the last digits as specified in the SynScan document.
        if len(hex_text) >= 6:
            value_24bit = int(hex_text[:6], 16)
        else:
            value_24bit = int(hex_text, 16)

        degrees = value_24bit * 360.0 / float(1 << 24)
        return degrees % 360.0

    def _get_standard_axis_position_deg(self, axis: Axis) -> float:
        """
        Get AZM-ALT:

            PC sends: 'Z'
            Mount replies, for example:
                "12AB,4000#"

        Values are 16-bit hexadecimal fractions of a revolution.
        """
        response = self._send_command(b"Z", timeout=self.POSITION_TIMEOUT_S)
        text = response.decode("ascii", errors="ignore")

        parts = text.split(",")

        if len(parts) != 2:
            raise ValueError("Invalid standard AZM-ALT response.")

        if axis == Axis.RA:
            hex_text = parts[0].strip()
        else:
            hex_text = parts[1].strip()

        if not hex_text:
            raise ValueError("Empty axis position field.")

        value_16bit = int(hex_text, 16)
        degrees = value_16bit * 360.0 / 65536.0
        return degrees % 360.0

    # ------------------------------------------------------------------
    # Speed and motion commands
    # ------------------------------------------------------------------

    def set_speed_deg_s(self, speed_deg_s: float):
        """
        Sets the speed for future motion commands.

        If the mount is already moving, the current slew rate is updated.
        """
        self.speed_deg_s = self._clamp_speed(speed_deg_s)

        if self.running:
            axis_code = self._axis_code(self.axis)

            if self.speed_deg_s <= 0.0:
                self._stop_all_axes()
            else:
                self._send_variable_slew(
                    axis_code,
                    self.direction,
                    self.speed_deg_s,
                )

    def start_motion(self, axis: Axis, direction: MotionDirection):
        """
        Starts continuous slew on the selected axis.

        Tracking is disabled before issuing the slew command.
        """
        with self._lock:
            self.axis = axis
            self.direction = direction

            if self.running:
                self._stop_all_axes()

            self._disable_tracking_for_measurement()

            if self.speed_deg_s <= 0.0:
                self._stop_all_axes()
                self.running = False
                return

            axis_code = self._axis_code(axis)

            self._send_variable_slew(
                axis_code,
                direction,
                self.speed_deg_s,
            )

            self.running = True

    def stop_motion(self):
        """
        Stops motion and restores tracking mode if it was saved.
        """
        with self._lock:
            try:
                self._stop_all_axes()
            finally:
                self.running = False
                self._restore_tracking_after_measurement()

    # ------------------------------------------------------------------
    # Internal motion helpers
    # ------------------------------------------------------------------

    def _axis_code(self, axis: Axis) -> int:
        if axis == Axis.RA:
            return self.AXIS_CODE_RA

        return self.AXIS_CODE_DEC

    def _clamp_speed(self, speed_deg_s: float) -> float:
        """
        Speed is treated as a positive magnitude.
        Direction is controlled separately.
        """
        speed = abs(float(speed_deg_s))

        if speed < 1e-6:
            return 0.0

        if speed > self.MAX_VARIABLE_SPEED_DEG_S:
            speed = self.MAX_VARIABLE_SPEED_DEG_S

        return speed

    def _encode_variable_rate(self, speed_deg_s: float):
        """
        SynScan variable rate encoding:

            rate_arcsec_s = speed_deg_s * 3600
            encoded = rate_arcsec_s * 4

        encoded is split into high and low bytes.
        """
        encoded = int(round(abs(speed_deg_s) * 3600.0 * 4.0))

        if encoded < 0:
            encoded = 0

        if encoded > 65535:
            encoded = 65535

        high = (encoded >> 8) & 0xFF
        low = encoded & 0xFF

        return high, low

    def _send_variable_slew(
        self,
        axis_code: int,
        direction: MotionDirection,
        speed_deg_s: float,
    ):
        """
        Variable-rate slew command.

        For RA/Azm positive:

            'P' & chr(3) & chr(16) & chr(6) & high & low & chr(0) & chr(0)

        For RA/Azm negative:

            'P' & chr(3) & chr(16) & chr(7) & high & low & chr(0) & chr(0)

        For DEC/Alt positive:

            'P' & chr(3) & chr(17) & chr(6) & high & low & chr(0) & chr(0)

        For DEC/Alt negative:

            'P' & chr(3) & chr(17) & chr(7) & high & low & chr(0) & chr(0)
        """
        if speed_deg_s <= 0.0:
            self._stop_axis(axis_code)
            return

        high, low = self._encode_variable_rate(speed_deg_s)

        if direction == MotionDirection.FORWARD:
            direction_byte = self.DIRECTION_POSITIVE
        else:
            direction_byte = self.DIRECTION_NEGATIVE

        command = b"P" + bytes([
            3,
            axis_code,
            direction_byte,
            high,
            low,
            0,
            0,
        ])

        self._send_command(command, timeout=self.RESPONSE_TIMEOUT_S)

    def _stop_axis(self, axis_code: int):
        """
        Stops one axis.

        Two actions are used for robustness:

        1. Fixed-rate stop command with rate byte 0.
        2. Variable-rate command with high/low rate bytes 0.
        """
        # Fixed-rate stop.
        fixed_stop_command = b"P" + bytes([
            2,
            axis_code,
            self.FIXED_DIRECTION_POSITIVE,
            0,
            0,
            0,
            0,
        ])

        try:
            self._send_command(fixed_stop_command, timeout=self.RESPONSE_TIMEOUT_S)
        except Exception:
            pass

        # Variable-rate zero stop.
        variable_stop_command = b"P" + bytes([
            3,
            axis_code,
            self.DIRECTION_POSITIVE,
            0,
            0,
            0,
            0,
        ])

        try:
            self._send_command(variable_stop_command, timeout=self.RESPONSE_TIMEOUT_S)
        except Exception:
            pass

    def _stop_all_axes(self):
        """
        Stops both axes and cancels any GOTO operation.
        """
        try:
            # Cancel GOTO.
            self._send_command(b"M", timeout=self.RESPONSE_TIMEOUT_S)
        except Exception:
            pass

        self._stop_axis(self.AXIS_CODE_RA)
        self._stop_axis(self.AXIS_CODE_DEC)
```

# 4. Notas importantes para NEQ6

## 4.1. Posición usada

El driver usa:

```text
z -> Get precise AZM-ALT
```

Para una NEQ6 ecuatorial alemana:

```text
AZM -> RA motor axis
ALT -> DEC motor axis
```

Esto es más adecuado para medir una rotación mecánica completa que usar coordenadas celestes RA/DEC.

Si la montura no está alineada, los valores AZM-ALT son relativos al punto donde se encendió, pero eso es válido para medir una rotación relativa desde la posición inicial.

---

## 4.2. Velocidad

La velocidad se introduce en grados/segundo.

El driver convierte:

```text
deg/s -> arcsec/s -> encoded = arcsec/s * 4
```

Límite teórico SynScan para velocidad variable:

```text
4.5507 deg/s
```

Si se solicita una velocidad mayor, el driver la limita automáticamente.

---

## 4.3. Tracking

El protocolo indica que los comandos de slew pueden interferir con el tracking.

Por eso el driver hace:

1. Leer modo de tracking actual.
2. Poner tracking en `0` — *Tracking off*.
3. Ejecutar el slew.
4. Al detener, restaurar el modo anterior.

---

## 4.4. Eje DEC

En una montura ecuatorial alemana, el eje DEC puede tener límites mecánicos o riesgo de colisión según la posición del tubo.

Aunque el software permita seleccionar DEC, debe verificar manualmente que una rotación completa es segura.

---

# 1. ¿De dónde sale la máxima sampling rate?

En el código anterior, la lista de velocidades del Flipper salía de:

```python
DEFAULT_SAMPLE_RATES = [10, 20, 50, 100, 200]
```

y el firmware de referencia tenía un límite superior artificial de:

```c
if (rate_hz > 1000) {
    rate_hz = 1000;
}
```

Ese valor de **1000 Hz** era un límite de diseño, no una garantía real.

La máxima tasa de muestreo real depende de:

1. El hardware del Flipper Zero.
2. El firmware personalizado.
3. La configuración del ADC.
4. La velocidad de conexión BLE.
5. El intervalo de conexión BLE.
6. El tamaño de los paquetes.
7. La calidad del enlace Bluetooth.
8. La carga de CPU del Flipper.

Por tanto, lo correcto es:

- El firmware del Flipper debe informar de su máxima tasa de muestreo soportada.
- La GUI debe consultar esa tasa al conectarse.
- La GUI debe mostrar al usuario el límite real.
- Si el firmware no responde, la GUI debe usar valores conservadores.

Para eso se puede usar el comando:

```text
CMD_GET_INFO
```

con respuesta:

```text
RESP_INFO
```

Más abajo le indico cómo añadirlo.

---

# 2. ¿Cómo sabe el usuario la máxima velocidad de la montura?

Para la NEQ6/SynScan, la velocidad variable está limitada por el propio protocolo SynScan.

El comando de slew variable codifica la velocidad como:

```text
encoded_rate = rate_arcsec_per_s * 4
```

y ese valor se envía en dos bytes:

```text
high byte + low byte
```

Por tanto:

```text
encoded_rate <= 65535
```

Entonces:

```text
rate_arcsec_per_s <= 65535 / 4
rate_arcsec_per_s <= 16383.75 arcsec/s
```

Pasado a grados/segundo:

```text
16383.75 / 3600 = 4.550694 deg/s
```

Por tanto, la máxima velocidad conocida en modo variable es:

```text
4.5507 deg/s
```

Ese valor debe mostrarse en la GUI.

Importante: los comandos SynScan de velocidad fija usan valores 1–9, pero el protocolo no define exactamente cuántos grados/segundo equivalen a cada valor fijo. Esos valores imitan las velocidades del mando manual. Por eso, si se desea una velocidad conocida en `deg/s`, debe usarse el modo variable, limitado a aproximadamente 4.55 `deg/s`.

Si se quiere ir más rápido usando velocidad fija 9, habría que calibrar manualmente esa velocidad midiendo el tiempo de una rotación conocida.

```python
    async def get_info(self):
        """
        Requests Flipper information.

        Expected minimal payload:

            uint16 max_sample_rate_hz
            uint16 current_sample_rate_hz
            uint16 adc_vref_mv
            uint8  flags
        """
        # Remove stale INFO responses.
        while not self.info_queue.empty():
            self.info_queue.get_nowait()

        await self.send_frame(CMD_GET_INFO)

        try:
            payload = await asyncio.wait_for(self.info_queue.get(), timeout=2.0)
        except asyncio.TimeoutError:
            return {}

        info = {}

        if len(payload) >= 2:
            info["max_sample_rate_hz"] = struct.unpack("<H", payload[0:2])[0]

        if len(payload) >= 4:
            info["current_sample_rate_hz"] = struct.unpack("<H", payload[2:4])[0]

        if len(payload) >= 6:
            info["adc_vref_mv"] = struct.unpack("<H", payload[4:6])[0]

        if len(payload) >= 7:
            info["flags"] = payload[6]

        return info
```

```c
#define MAX_SAMPLE_RATE_HZ  200U

static void handle_get_info(void)
{
    /*
     * INFO payload:
     *
     * uint16 max_sample_rate_hz
     * uint16 current_sample_rate_hz
     * uint16 adc_vref_mv
     * uint8  flags
     */

    uint8_t payload[7];

    uint16_t max_rate = MAX_SAMPLE_RATE_HZ;
    uint16_t current_rate = sample_rate_hz;
    uint16_t adc_vref_mv = 2500;
    uint8_t flags = 0;

    memcpy(&payload[0], &max_rate, sizeof(max_rate));
    memcpy(&payload[2], &current_rate, sizeof(current_rate));
    memcpy(&payload[4], &adc_vref_mv, sizeof(adc_vref_mv));
    payload[6] = flags;

    send_frame(RESP_INFO, payload, sizeof(payload));
}
```

Y en el manejador de comandos:

```c
static void handle_command_frame(uint8_t packet_type, const uint8_t *payload, uint8_t len)
{
    switch (packet_type) {
        case CMD_GET_INFO:
            handle_get_info();
            break;

        case CMD_SYNC_REQ:
            handle_sync_request(payload, len);
            break;

        case CMD_SET_RATE:
            handle_set_rate(payload, len);
            break;

        case CMD_START:
            sampling = true;
            send_frame(RESP_START, NULL, 0);
            break;

        case CMD_STOP:
            sampling = false;
            send_frame(RESP_STOP, NULL, 0);
            break;

        default:
            break;
    }
}
```

Importante: el valor:

```c
#define MAX_SAMPLE_RATE_HZ 200U
```

debe ser el máximo real validado en su firmware y enlace BLE.

Si usted valida que el sistema funciona a 500 Hz o 1000 Hz, puede aumentarlo. Pero no debería mostrarse al usuario un límite que no haya sido probado.

```python
    @asyncSlot()
    async def on_connect_mount(self):
        # If the user selected a simulated mount.
        port_text = self.port_combo.currentText().strip()
        port_data = self.port_combo.currentData()

        if port_data:
            port = str(port_data)
        else:
            port = port_text.split(" - ")[0].strip()

        if not port or port == "No serial ports found":
            QMessageBox.warning(
                self,
                "Mount connection",
                "No valid serial port selected.",
            )
            return

        try:
            if port.upper() == "SIM":
                self.mount = SimulatedMount()
            else:
                self.mount = Neq6Serial(port)

            await asyncio.to_thread(self.mount.connect)

            self.btn_mount_connect.setEnabled(False)
            self.btn_mount_disconnect.setEnabled(True)

            self._update_mount_speed_limit()

            self.serial_log.append(f"Mount connected on {port}.")

        except Exception as exc:
            self.mount = None

            QMessageBox.warning(
                self,
                "Mount connection",
                f"Could not connect to mount on {port}.\n\n{exc}",
            )

            self.serial_log.append(f"Mount connection failed on {port}: {exc}")

    @asyncSlot()
```

```python
    def _populate_sample_rate_combo(self, max_rate_hz: int):
        candidate_rates = [1, 2, 5, 10, 20, 50, 100, 200, 500, 1000]

        allowed = [rate for rate in candidate_rates if rate <= max_rate_hz]

        if not allowed:
            allowed = [max_rate_hz]

        if max_rate_hz not in allowed:
            allowed.append(max_rate_hz)

        self.rate_combo.clear()

        for rate in allowed:
            self.rate_combo.addItem(str(int(rate)))

        # Prefer 100 Hz if available; otherwise choose the highest allowed.
        if "100" in [str(rate) for rate in allowed]:
            self.rate_combo.setCurrentText("100")
        else:
            self.rate_combo.setCurrentText(str(allowed[-1]))
```

## 6.10. Consola serie para enviar comandos SynScan

Añada:

```python
    def _parse_user_command(self, text: str, hex_mode: bool) -> bytes:
        text = text.strip()

        if not text:
            raise ValueError("Empty command.")

        if hex_mode:
            cleaned = (
                text.replace(" ", "")
                    .replace(",", "")
                    .replace("0x", "")
                    .replace("0X", "")
            )

            return bytes.fromhex(cleaned)

        return text.encode("ascii")

    @asyncSlot()
    async def on_send_serial_command(self):
        if self.mount is None or not self.mount.connected:
            QMessageBox.warning(
                self,
                "Serial command",
                "Mount is not connected.",
            )
            return

        text = self.cmd_edit.text()

        try:
            command = self._parse_user_command(text, self.hex_check.isChecked())
        except Exception as exc:
            QMessageBox.warning(
                self,
                "Serial command",
                f"Could not parse command.\n\n{exc}",
            )
            return

        try:
            response = await asyncio.to_thread(
                self.mount.send_user_command,
                command,
                1.0,
            )

            response_hex = response.hex(" ").upper()
            response_ascii = "".join(
                chr(b) if 32 <= b < 127 else "."
                for b in response
            )

            self.serial_log.append(
                f"TX: {command.hex(' ').upper()} | "
                f"RX: {response_hex} | ASCII: {response_ascii}"
            )

        except Exception as exc:
            self.serial_log.append(
                f"TX: {command.hex(' ').upper()} | Error: {exc}"
            )

            QMessageBox.warning(
                self,
                "Serial command",
                f"Command failed.\n\n{exc}",
            )
```

# 8. Cómo mostrar al usuario la máxima sampling rate del Flipper

Cuando la GUI se conecte al Flipper, debe enviar:

```text
CMD_GET_INFO
```

Si el firmware responde, por ejemplo:

```text
max_sample_rate_hz = 200
```

la GUI debe mostrar:

```text
Flipper max sample rate: 200 Hz
```

y el selector de sample rate solo debe permitir valores válidos hasta 200 Hz.

Si el firmware no responde, la GUI debe mostrar:

```text
Flipper max sample rate: unknown
```

y usar valores conservadores.

# 9. Nota sobre el pairing BLE

El emparejamiento BLE depende del sistema operativo.

En muchos casos, el Flipper Zero no necesita emparejamiento explícito para usar Nordic UART Service. Sin embargo, si su sistema requiere emparejamiento:

- Windows puede mostrar una notificación de emparejamiento.
- Linux puede requerir emparejamiento desde `bluetoothctl`.
- El método `pair()` de `bleak` puede funcionar en algunos backends, pero no es idéntico en todos los sistemas.

Por eso el código incluye:

```python
self.pair_check = QCheckBox("Pair on connect")
```

Si el emparejamiento automático falla, la solución alternativa es emparejar manualmente desde el sistema operativo y luego conectar la aplicación.

# 10. Resumen de límites que debe ver el usuario

La GUI debe mostrar claramente:

## Para la montura

```text
Max SynScan variable speed: 4.5507 deg/s
```

Esto sale del protocolo SynScan:

```text
65535 / 4 / 3600 = 4.5507 deg/s
```

## Para el Flipper

```text
Flipper max sample rate: X Hz
```

Esto debe salir del firmware del Flipper mediante `CMD_GET_INFO`.

Si el firmware no informa del límite, el programa debe usar valores conservadores y mostrar:

```text
Flipper max sample rate: unknown
```

No es recomendable mostrar al usuario una máxima tasa de muestreo fija, por ejemplo 1000 Hz, si esa tasa no ha sido validada por el firmware real y por el enlace BLE.
